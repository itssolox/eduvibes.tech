Practical 1: Simple Reflex Agent - Vacuum Cleaner

Simple Reflex Agent • PEAS • Discrete Environment

Aim Theory Algorithm Source Code Code Explanation Output Viva Voce (12) Exam Variations

Aim & Objective

To design and implement a Simple Reflex Agent for the two-room Vacuum Cleaner World that perceives room status and location, and executes rational cleaning and movement actions based on condition-action rules.

Theory & Core Concepts

PEAS ElementSystem Description for Practical 1
Performance MeasureMaximize clean rooms; minimize energy consumption and time spent moving.
EnvironmentTwo interconnected rooms (A and B); each room status is either Clean or Dirty.
ActuatorsSuction motor (Suck), movement motors (Left, Right).
SensorsDirt detection sensor (Clean/Dirty), Location sensor (Room A / Room B).
  • Agent Concept: An agent is anything that perceives its environment through sensors and acts upon it via actuators.
  • Simple Reflex Architecture: Actions are chosen solely using the current percept (location, dirt status) and condition-action (IF-THEN) rules. The agent maintains zero history or memory of past states.
  • Partial Observability: The agent only perceives the room it currently occupies, not both rooms simultaneously. The global world state is known only to the simulator.
  • Rationality: In this setup, cleaning a dirty room is immediately rational. However, once both rooms are clean, a pure reflex agent with no memory or stopping check would oscillate back and forth indefinitely; the simulation provides the external termination condition.

Step-by-Step Algorithm & Dry Run

  1. Receive current percept (location, status) from the environment.
  2. Evaluate condition-action rules: If status == 'Dirty', action is 'Suck'.
  3. If status == 'Clean' and location == 'A', action is 'Right'.
  4. If status == 'Clean' and location == 'B', action is 'Left'.
  5. Apply action to simulator: update room status or agent location.
  6. Record step in history and repeat until the simulator detects all rooms are Clean.

# Practical 1: Simple Reflex Agent - Vacuum Cleaner World

# Decision function for the reflex agent based on current percept
def reflex_agent(location, status):
    if status == "Dirty":                     # If the room is dirty
        return "Suck"                         # Action: suck the dirt
    elif location == "A":                     # If room A is already clean
        return "Right"                        # Action: move to room B
    else:                                     # If room B is already clean
        return "Left"                         # Action: move to room A

# Main simulation function
def main():
    location = "A"                            # Start location of the vacuum agent
    rooms = {}                                # Dictionary to store cleanliness status
    rooms["A"] = "Dirty"                      # Initial status of room A
    rooms["B"] = "Dirty"                      # Initial status of room B
    
    print("Initial:", rooms, "Location:", location)
    step = 1                                  # Step counter
    
    # Run loop while either room A or room B is still dirty
    while rooms["A"] == "Dirty" or rooms["B"] == "Dirty":
        status = rooms[location]              # Sense dirt in current room
        action = reflex_agent(location, status) # Decide action based on reflex rules
        
        print(str(step) + ". At " + location + ", status=" + status + ": " + action)
        
        # Apply the action to update the environment
        if action == "Suck":
            rooms[location] = "Clean"         # Room becomes clean
        elif action == "Right":
            location = "B"                    # Agent moves to room B
        elif action == "Left":
            location = "A"                    # Agent moves to room A
            
        step = step + 1                       # Increment step count
        
    print("Final:", rooms)
    print("Actions:", step - 1)
    print("Simulation stopped: both rooms are clean.")

if __name__ == "__main__":
    main()

Detailed Code Explanation

Function-by-function breakdown and key variables explaining the internal logic:

  • rooms is a dictionary: {"A": "Dirty", "B": "Dirty"}. location is either "A" or "B".
  • reflex_agent(location, status) is the decision-making part. Dirty means Suck; clean A means Right; clean B means Left.
  • simulate() validates the input, copies the room dictionary, obtains an action and applies it to the environment.
  • history.append(...) records the old percept and selected action for printing. This recording belongs to the simulator; the reflex function does not read history.
  • The while loop ends when the simulator finds no dirty room. Without a global stopping check or added memory, the simple reflex rules would keep moving between two clean rooms.
  • main() sets the input and prints each action. Change LOCATION and ROOMS for other cases.

Dry run: (A, Dirty) -> Suck -> (A, Clean) -> Right -> (B, Dirty) -> Suck. Both rooms are now clean; total 3 actions.

Viva Voce Questions & Model Answers

Frequently asked laboratory exam and oral viva questions with model examiner responses:

Q1. What is an intelligent agent?
An entity that perceives its environment through sensors and acts through actuators to achieve a performance objective.
Q2. What is a simple reflex agent?
An agent that selects an action using only its current percept and fixed condition-action rules.
Q3. What is a percept here?
The current room's location and cleanliness status, such as (A, Dirty).
Q4. What are sensors and actuators here?
Sensors detect location and dirt. Actuators perform cleaning and movement.
Q5. What is a condition-action rule?
An IF-THEN rule; for example, IF the current room is dirty, THEN clean it.
Q6. What is PEAS for this task?
Performance: cleanliness with low time/energy cost. Environment: two rooms. Actuators: suck and move. Sensors: current location and dirt sensor.
Q7. Does the agent remember previous rooms?
No. The action function has no stored history or internal model.
Q8. Is the environment fully observable?
With only the current room's status visible, the whole two-room environment is partially observable. The simulator knows both rooms, but the agent does not.
Q9. What makes an action rational?
It should maximise expected performance using available information. Cleaning dirt is useful, but unnecessary movement wastes energy if movement has a cost.
Q10. Why is a dictionary used?
It maps room labels directly to their statuses, making lookup and updates easy.
Q11. Can the reflex agent decide that both rooms are clean?
Not from one local percept alone. The simulation stops externally; a memory-based agent could track both rooms.
Q12. What are its limitations?
No memory, no multi-step planning and repeated actions when the current percept is insufficient.

Practical 2: Model-Based Intelligent Agent - Grid Navigation

Model-Based Agent • Local Sensing • BFS Planning

Aim Theory Algorithm Source Code Code Explanation Output Viva Voce (12) Exam Variations

Aim & Objective

To implement a Model-Based Intelligent Agent that navigates an initially unknown obstacle grid by sensing local surroundings, maintaining an internal world map, and planning paths using Breadth-First Search (BFS).

Theory & Core Concepts

PEAS ElementSystem Description for Practical 2
Performance MeasureReach the target goal G with minimum path steps without colliding with obstacles.
Environment2D rectangular grid with Start (S), Goal (G), Free cells (.), and Obstacles (X).
ActuatorsOrthogonal movement (Up, Down, Left, Right).
SensorsLocal sensor revealing current cell and its 4 direct neighbours.
  • Model-Based Architecture: To handle partial observability, the agent maintains an internal world model (model) tracking discovered free cells, obstacles, and unexplored cells (?).
  • Unknown Cell Safety: Cells marked ? are never traversed by the planner until confirmed safe/free by local sensing.
  • Dual-Stage Planning: The agent first runs BFS on known free cells to plan to the Goal G. If the goal is not yet reachable through known territory, it plans to the nearest reachable unvisited free cell to explore.
  • BFS Guarantee: On an unweighted grid, BFS finds the shortest route across known free cells to the selected sub-target.

Step-by-Step Algorithm & Dry Run

  1. Initialize internal model grid with ? (unseen) using simple nested loops.
  2. Sense current cell and 4 adjacent orthogonal neighbours; record actual contents into internal model.
  3. Mark current position as visited.
  4. While position != goal:
  5.   a. Run BFS planner targeting the Goal G using only known free cells (., S, G).
  6.   b. If route to goal exists, follow it.
  7.   c. If no route to goal, identify all sensed, free, unvisited cells and BFS plan to the nearest one (exploration mode).
  8.   d. If no exploration target is reachable, terminate with failure (unreachable goal).
  9.   e. Traverse each step of the planned route, sense newly adjacent cells after each move, and replan.

from collections import deque

grid = [
    ["S", ".", ".", "X", "."],
    [".", "X", ".", "X", "."],
    [".", "X", ".", ".", "."],
    [".", ".", ".", "X", "."],
    ["X", "X", ".", ".", "G"]
]
rows, cols = len(grid), len(grid[0])

for i in range(rows):
    for j in range(cols):
        if grid[i][j] == "S": start = (i, j)
        if grid[i][j] == "G": goal = (i, j)

directions = [(0, 1, "Right"), (1, 0, "Down"), (0, -1, "Left"), (-1, 0, "Up")]
queue = deque([start])
visited = {start}
parent = {}

while queue:
    curr = queue.popleft()
    if curr == goal: break
    r, c = curr
    for dr, dc, move in directions:
        nr, nc = r + dr, c + dc
        if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] != "X" and (nr, nc) not in visited:
            visited.add((nr, nc))
            parent[(nr, nc)] = (curr, move)
            queue.append((nr, nc))

if goal not in visited:
    print("No path found!")
else:
    path, curr = [], goal
    while curr != start:
        curr, move = parent[curr]
        path.append(move)
    path.reverse()
    print("Shortest Path:", " -> ".join(path))
    print("Total Steps:", len(path))

# Practical 2: Model-Based Agent - Grid Navigation with Local Sensing & BFS
from collections import deque                 # Import deque for fast queue operations in BFS

# 4 Orthogonal Movement Directions: (row offset, column offset)
DIRECTIONS = [
    (-1, 0),                                  # Move UP
    (1, 0),                                   # Move DOWN
    (0, -1),                                  # Move LEFT
    (0, 1)                                    # Move RIGHT
]

# The actual real-world environment (obstacles 'X' are unknown to the agent at the start)
GRID = [
    ["S", ".", ".", "X", "."],
    [".", "X", ".", "X", "."],
    [".", "X", ".", ".", "."],
    [".", ".", ".", "X", "."],
    ["X", "X", ".", ".", "G"]
]

ROWS = len(GRID)                              # Number of grid rows (5)
COLS = len(GRID[0])                           # Number of grid columns (5)

# Find coordinates of Start (S) and Goal (G) using simple loops
start_pos = None                              # Will hold starting (row, col)
goal_pos = None                               # Will hold goal (row, col)
for r in range(ROWS):
    for c in range(COLS):
        if GRID[r][c] == "S":
            start_pos = (r, c)                # S is at (0, 0)
        elif GRID[r][c] == "G":
            goal_pos = (r, c)                 # G is at (4, 4)

# Create agent's internal memory map using plain loops (NO list comprehensions)
model = []
for r in range(ROWS):
    row = []
    for c in range(COLS):
        row.append("?")                       # Fill with '?' meaning unseen/unknown cell
    model.append(row)

visited = set()                               # Set to remember which cells the agent visited
path = []                                     # List to record the sequence of visited cells

# Function to find all valid adjacent neighbours within grid boundaries
def get_neighbours(r, c):
    valid_neighbours = []                     # List to store valid neighbour coordinates
    for dr, dc in DIRECTIONS:                 # Loop through each of the 4 directions
        nr = r + dr                           # Neighbour row
        nc = c + dc                           # Neighbour column
        if nr >= 0 and nr < ROWS and nc >= 0 and nc < COLS: # Check within boundaries
            valid_neighbours.append((nr, nc)) # Valid coordinate inside grid
    return valid_neighbours                   # Return list of coordinates

# Local sensing: read actual grid content of current cell and its 4 neighbours into model
def sense(r, c):
    model[r][c] = GRID[r][c]                  # Reveal current cell
    neighbour_cells = get_neighbours(r, c)    # Get adjacent coordinates
    for nr, nc in neighbour_cells:
        model[nr][nc] = GRID[nr][nc]          # Reveal neighbour cell

# BFS pathfinding using ONLY cells known to be safe in the agent's internal model
def bfs(start, targets):
    queue = deque()                           # Create FIFO queue
    queue.append(start)                       # Enqueue start position
    parent = {}                               # Dictionary to store parent of each cell
    parent[start] = None                      # Start cell has no predecessor
    
    while len(queue) > 0:                     # While queue has positions to explore
        curr = queue.popleft()                # Pop oldest cell (FIFO)
        
        if curr in targets:                   # Check if current cell is a target
            route = []                        # List to reconstruct the route
            while curr is not None:           # Trace backwards to start
                route.append(curr)
                curr = parent[curr]           # Move to parent cell
            route.reverse()                   # Reverse to get START -> TARGET order
            return route                      # Return planned path
            
        curr_r = curr[0]                      # Current row
        curr_c = curr[1]                      # Current column
        
        for nxt in get_neighbours(curr_r, curr_c): # Check all 4 neighbours
            nr = nxt[0]
            nc = nxt[1]
            cell_val = model[nr][nc]          # Sensed value in internal map
            # Move only through cells known to be free ('.', 'S', or 'G')
            if (cell_val == "." or cell_val == "S" or cell_val == "G") and nxt not in parent:
                parent[nxt] = curr            # Save predecessor link
                queue.append(nxt)             # Enqueue neighbour
                
    return None                               # Return None if no path found

def main():
    curr_pos = start_pos                      # Place agent at start position
    path.append(curr_pos)                     # Record start in travel path
    visited.add(curr_pos)                     # Mark start as visited
    sense(curr_pos[0], curr_pos[1])           # Perform initial local sensing
    
    # Loop until the agent reaches the goal
    while curr_pos != goal_pos:
        # Step 1: Try planning directly to the goal
        goal_target_set = {goal_pos}
        route = bfs(curr_pos, goal_target_set)
        
        # Step 2: If goal not reachable yet, find nearest unvisited known free cell to explore
        if route is None:
            unexplored = []                   # Collect known free cells not visited yet
            for r in range(ROWS):
                for c in range(COLS):
                    cell_val = model[r][c]
                    is_free = (cell_val == "." or cell_val == "S" or cell_val == "G")
                    if is_free and (r, c) not in visited:
                        unexplored.append((r, c)) # Candidate exploration cell
                        
            route = bfs(curr_pos, set(unexplored)) # Plan route to nearest exploration cell
            
        # Step 3: If still no route, reachable area is exhausted
        if route is None:
            print("No route: reachable area exhausted.")
            return
            
        # Step 4: Follow the planned route step-by-step
        for i in range(1, len(route)):
            next_step = route[i]              # Next step in path
            curr_pos = next_step              # Move agent
            path.append(curr_pos)             # Record step
            visited.add(curr_pos)             # Mark as visited
            sense(curr_pos[0], curr_pos[1])   # Sense new surroundings after move
            if curr_pos == goal_pos:          # Stop walking if goal reached
                break
                
    print("Goal reached!")
    print("Actual travel path:", path)
    print("Moves:", len(path) - 1)
    print("Remembered map (? = unseen):")
    for row in model:
        print(" ".join(row))                  # Print final remembered grid

if __name__ == "__main__":
    main()

Detailed Code Explanation

Function-by-function breakdown and key variables explaining the internal logic:

  • GRID is a list of equal-length strings. S is start, G is goal, . is free and X is blocked.
  • ModelBasedAgent.__init__() creates the position, known goal coordinates, visited set, actual travel path and a model initially filled with ?.
  • neighbours() generates only in-bounds up/down/left/right coordinates. It does not read hidden grid contents.
  • sense() is the only method that reads actual cell contents. It copies the current cell and its immediate neighbours into the model.
  • plan(targets) runs BFS over known free cells. Its parent dictionary both records visited search states and reconstructs a route.
  • run() first tries planning to the goal. If that fails, it plans to the nearest reachable known-free cell that the agent has not visited.
  • It follows the route, senses during movement and then replans. If no reachable exploration target remains, it reports failure.
  • The actual grid is stored for simulation, but the planner uses self.model, not the full environment.

The default example reaches the goal in 20 actual moves. This includes exploration; it is not a claim that the globally shortest route has 20 moves.

Viva Voce Questions & Model Answers

Frequently asked laboratory exam and oral viva questions with model examiner responses:

Q1. What is a model-based agent?
An agent that maintains internal state representing what it has learned about the environment.
Q2. How does it differ from a simple reflex agent?
A simple reflex agent uses only the current percept. A model-based agent combines the percept with remembered state.
Q3. What is the internal state in this code?
The discovered map, position, visited locations and movement history.
Q4. What does `?` mean?
The cell has not yet been sensed. It is neither assumed free nor assumed blocked for planning; traversal is disallowed until known free.
Q5. Why is the environment partially observable?
The sensor reveals only the current cell and adjacent cells, not the whole grid.
Q6. Why use BFS?
On the known grid with equal-cost moves, BFS finds a shortest route to a selected reachable target.
Q7. Does this guarantee the globally shortest start-to-goal trip?
No. Exploration is needed because the full map is initially unknown.
Q8. Why keep a visited set?
It prevents selecting already explored cells as fresh exploration targets. Returning through a visited cell may still be necessary.
Q9. What happens at a dead end?
The agent can plan back through remembered free cells to another unvisited target.
Q10. What happens when the goal is unreachable?
After exhausting reachable exploration targets, it returns failure instead of moving forever.
Q11. Is this only a reflex agent?
It is a model-based agent with a planning component; the BFS component additionally uses goals.
Q12. What assumptions are made?
A static rectangular grid, four-direction movement, known map dimensions and goal coordinates, and reliable local sensing.

Informed Search • Manhattan Distance • Admissible Heuristic

Aim Theory Algorithm Source Code Code Explanation Output Viva Voce (15) Exam Variations

Aim & Objective

To implement the A* heuristic search algorithm to solve the 8-puzzle problem using Manhattan distance as an admissible and consistent heuristic.

Theory & Core Concepts

  • A* Evaluation Function: f(n) = g(n) + h(n), where g(n) is the exact cost from start to node n, and h(n) is the estimated remaining cost to the goal.
  • Manhattan Distance: Sum of horizontal and vertical distances of each numbered tile from its goal position: h(n) = Σ (|r_i - r_goal| + |c_i - c_goal|) for tiles 1..8. The blank tile 0 is excluded so moves are not double counted.
  • Admissibility & Consistency: Manhattan distance is admissible (never overestimates) because each sliding move can only reduce the distance of one tile by 1 grid step. It is also consistent (monotonic), guaranteeing an optimal shortest path.
  • Inversion Parity Solvability: An inversion occurs when a tile with a larger number precedes a tile with a smaller number in row-major order (ignoring 0). In a 3x3 puzzle, blank moves preserve inversion parity. Start and Goal must have the same parity (both even or both odd); otherwise the puzzle is mathematically unsolvable.

Step-by-Step Algorithm & Dry Run

  1. Validate state (all digits 0..8 present) and verify parity(start) == parity(goal).
  2. Initialize priority queue (min-heap) with (f=h(start), g=0, start).
  3. Initialize best_g = {start: 0} and parent = {start: (None, 'START')}.
  4. While frontier is not empty:
  5.   a. Pop state with lowest f. If g > best_g[current], discard stale entry.
  6.   b. If current == goal, reconstruct solution path and return.
  7.   c. Increment expanded node counter.
  8.   d. Generate legal blank swaps (UP, DOWN, LEFT, RIGHT).
  9.   e. For each neighbour, compute new_g = g + 1. If new_g < best_g[nxt], record best_g, parent, calculate f = new_g + h(nxt), and push to min-heap.

# Practical 3: Informed Search - A* Algorithm for 8-Puzzle Problem
import heapq                                  # Import heapq for priority queue (min-heap)

# Check if puzzle state is solvable using inversion count
def is_solvable(state):
    tiles = []                                # List to store tiles excluding blank
    for x in state:
        if x != 0:                            # Ignore blank tile (0)
            tiles.append(x)
            
    inversions = 0                            # Count of pairs in reverse order
    for i in range(len(tiles)):
        for j in range(i + 1, len(tiles)):
            if tiles[i] > tiles[j]:           # If a larger number appears before smaller
                inversions = inversions + 1   # Count as an inversion
                
    return inversions % 2 == 0                # Solvable if count of inversions is even

# Calculate Manhattan distance heuristic: sum of distances of tiles to goal positions
def manhattan_distance(state, goal_pos):
    distance = 0                              # Initialize total distance
    for i in range(len(state)):
        tile = state[i]
        if tile != 0:                         # Do not count the blank tile (0)
            curr_r = i // 3                   # Row index in 3x3 grid (0, 1, or 2)
            curr_c = i % 3                    # Column index in 3x3 grid (0, 1, or 2)
            target_r = goal_pos[tile][0]      # Goal row for this tile
            target_c = goal_pos[tile][1]      # Goal column for this tile
            distance = distance + abs(curr_r - target_r) + abs(curr_c - target_c)
    return distance                           # Return total heuristic value h(n)

# Generate valid next states by moving the blank tile (0)
def get_neighbours(state):
    neighbours = []                           # List to store (new_state, move_name)
    blank = state.index(0)                    # Find index position of blank tile (0)
    r = blank // 3                            # Blank row (0, 1, or 2)
    c = blank % 3                             # Blank column (0, 1, or 2)
    
    # 4 possible directions to slide the blank: (name, dr, dc)
    moves = [
        ("UP", -1, 0),
        ("DOWN", 1, 0),
        ("LEFT", 0, -1),
        ("RIGHT", 0, 1)
    ]
    
    for move_name, dr, dc in moves:           # Check each direction
        nr = r + dr                           # New blank row
        nc = c + dc                           # New blank column
        if nr >= 0 and nr < 3 and nc >= 0 and nc < 3: # Check within 3x3 boundaries
            new_blank = nr * 3 + nc           # Convert row, col back to 1D index
            board = list(state)               # Convert tuple to mutable list
            temp = board[blank]               # Standard swap using temp variable
            board[blank] = board[new_blank]
            board[new_blank] = temp
            neighbours.append((tuple(board), move_name)) # Save new board tuple and move
    return neighbours                         # Return list of reachable neighbours

# A* Search algorithm implementation
def astar(start, goal):
    if not is_solvable(start):                # Check solvability before searching
        print("No solution: initial and goal inversion parities differ.")
        return None, 0
        
    # Precompute goal coordinates (r, c) for each tile using a plain loop
    goal_pos = {}
    for i in range(len(goal)):
        tile = goal[i]
        goal_pos[tile] = (i // 3, i % 3)
        
    # Priority queue (min-heap) stores entries: (f_score, g_cost, state)
    frontier = []
    initial_h = manhattan_distance(start, goal_pos) # Heuristic estimate for start
    heapq.heappush(frontier, (initial_h, 0, start)) # Push start state with f = 0 + h
    
    best_g = {}                               # Stores lowest g-cost found for each state
    best_g[start] = 0
    parent = {}                               # Stores parent state and action taken
    parent[start] = (None, "START")
    expanded_nodes = 0                        # Count of expanded nodes
    
    while len(frontier) > 0:                  # Loop until priority queue is empty
        f, g, current = heapq.heappop(frontier) # Pop state with lowest f = g + h
        
        if g > best_g.get(current, float("inf")): # Skip if a cheaper route was already processed
            continue
            
        if current == goal:                   # Check if goal board is reached
            path = []                         # List to reconstruct solution path
            while current is not None:        # Follow parent pointers back to start
                prev_state, action = parent[current]
                path.append((current, action)) # Add to path
                current = prev_state          # Step backward
            path.reverse()                    # Reverse path to get START -> GOAL order
            return path, expanded_nodes
            
        expanded_nodes = expanded_nodes + 1   # Increment expanded nodes count
        
        for next_state, action in get_neighbours(current): # Explore legal moves
            new_g = g + 1                     # Each sliding move has a step cost of 1
            if new_g < best_g.get(next_state, float("inf")): # If a shorter route is found
                best_g[next_state] = new_g    # Record the new cheapest g-cost
                parent[next_state] = (current, action) # Record parent and action
                h = manhattan_distance(next_state, goal_pos) # Compute heuristic h
                new_f = new_g + h             # Compute total evaluation f = g + h
                heapq.heappush(frontier, (new_f, new_g, next_state)) # Push to priority queue
                
    return None, expanded_nodes               # Return None if no solution found

Function-by-function breakdown and key variables explaining the internal logic:

  • A state is a tuple of nine integers; 0 means blank. Tuple states can be dictionary keys.

A heuristic that never overestimates the true cheapest remaining cost.

For every edge n to n', h(n) <= cost(n,n') + h(n'); the goal has h=0.

Each legal move moves one numbered tile by only one grid step. Ignoring other tiles cannot require more moves than the real constrained problem.

One action moves both a tile and the blank. Counting both can overestimate the required number of moves.

Greedy uses h alone; A* uses g+h. Greedy does not generally guarantee a cheapest solution.

The frontier of discovered states awaiting expansion, held in a priority queue.

Conventionally the set of expanded states. This implementation instead keeps best costs and skips stale heap entries, allowing cheaper routes to be processed.

With an admissible heuristic and correct handling of improved paths under standard nonnegative-cost search conditions. Consistency is sufficient when expanded states are never reopened. Our Manhattan heuristic is consistent.

Aim & Objective

To implement and compare the Minimax algorithm and Alpha-Beta pruning on a two-player zero-sum binary game tree and evaluate the reduction in visited nodes.

Theory & Core Concepts

  • Adversarial Search: Search in competitive environments where two opposing agents alternate moves. MAX aims to maximize the terminal utility, while MIN aims to minimize it.
  • Minimax Principle: Recursively computes the value of each node: MAX nodes take max(left, right), MIN nodes take min(left, right).
  • Alpha-Beta Bounds: Maintains two cutoff thresholds:
    • α (Alpha): The best (highest) score MAX can guarantee along the search path.
    • β (Beta): The best (lowest) score MIN can enforce along the search path.
  • Pruning Condition: Whenever α ≥ β, the current branch cannot affect the root decision; the search terminates immediately at that node.
  • Optimality Invariance: Alpha-Beta pruning returns the exact same root game value as full Minimax, but reduces time complexity from O(b^d) to as low as O(b^(d/2)) with optimal move ordering.

Step-by-Step Algorithm & Dry Run

  1. Define terminal leaf scores in power-of-2 array, and calculate tree depth.
  2. Minimax(leaves, depth, index, is_maximizing):
    If depth is 0, return leaves[index]. Recurse on left child 2*index and right child 2*index+1. Return max() if maximizing else min().
  3. AlphaBeta(leaves, depth, index, is_maximizing, α, β):
    If depth is 0, return leaves[index].
    For each child in (2*index, 2*index+1):
      Recurse and obtain child score.
      If maximizing: update value = max(value, score), α = max(α, value).
      If minimizing: update value = min(value, score), β = min(β, value).
      If α ≥ β: break (prune remaining siblings).
    Return value.

                parent[next_state] = (curr, action) # Mark visited and record parent
                queue.append(next_state)      # Enqueue state for future expansion
                
    return None, expanded_count               # Return None if no path found

Aim & Objective

To solve 9x9 Sudoku puzzles using Constraint Satisfaction Problem (CSP) methods: Plain Backtracking vs Constraint Propagation with Minimum Remaining Values (MRV).

Theory & Core Concepts

  • CSP Formulation: Variables = 81 cells (empty cells are search variables); Domain = digits {1..9}; Constraints = All-Different in each row, each column, and each 3x3 subgrid.
  • Constraint Propagation: If any unfilled cell has exactly one valid candidate digit remaining, it is filled immediately as a forced assignment without branching. This repeats until no singletons remain.
  • Minimum Remaining Values (MRV): When branching is required, select the unassigned cell with the smallest domain (fewest candidates) to minimize the branching factor and detect dead ends immediately.
  • Performance Comparison: Plain backtracking makes 9,127 calls, 9,126 guesses, and 9,074 failed branches. Propagation + MRV solves the exact same puzzle in 1 call, 0 guesses, and 52 forced assignments!

Step-by-Step Algorithm & Dry Run

  1. Compute legal candidate digits for any cell: DIGITS - (used_row | used_col | used_box) using simple loops.
  2. propagate(board): Repeatedly scan all empty cells. If any has 0 candidates, return False (contradiction). If a cell has 1 candidate, assign it and continue. When no single-candidate cells remain, return True.
  3. solve(board, use_mrv):
      a. If improved mode: run propagate(); if contradiction, return None.
      b. Find all empty cells. If none remain, return board (solved).
      c. In improved mode: select cell with min(candidates) (MRV). In plain mode: select first empty cell.
      d. For each candidate value: create board copy, set value, recurse. If valid, return solution.
      e. Backtrack and return None.

def get_candidates(board, r, c):
    used = set()                              # Set of digits already present
    
    # 1. Collect numbers in the same row
    for val in board[r]:
        if val != 0:
            used.add(val)
            
    # 2. Collect numbers in the same column
    for i in range(9):
        val = board[i][c]
        if val != 0:
            used.add(val)
            
    # 3. Collect numbers in the 3x3 box
    box_r = (r // 3) * 3                      # Top row of 3x3 box
    box_c = (c // 3) * 3                      # Left column of 3x3 box
    for i in range(box_r, box_r + 3):
        for j in range(box_c, box_c + 3):
            val = board[i][j]
            if val != 0:
                used.add(val)
                
    # 4. Find all digits from 1 to 9 that are not used
    candidates = []
    for d in range(1, 10):
        if d not in used:
            candidates.append(d)
            
    return candidates                         # Return list of valid candidate digits

# Single-candidate constraint propagation: repeatedly fill forced single candidates
def propagate(board, stats):
    while True:                               # Repeat until no more forced cells exist
        changed = False                       # Flag to track if any cell was filled
        for r in range(9):
            for c in range(9):
                if board[r][c] == 0:          # If cell is empty
                    candidates = get_candidates(board, r, c) # Find valid digits
                    if len(candidates) == 0:  # Dead end: no valid digit possible!
                        return False          # Return False to trigger backtracking
                    if len(candidates) == 1:  # Forced value: only 1 legal digit exists
                        board[r][c] = candidates[0] # Fill cell immediately
                        stats["forced"] = stats["forced"] + 1
                        changed = True        # Mark that board changed
        if not changed:                       # If no cells were forced in this pass
            return True                       # Propagation successful

# Backtracking solver function
def solve(board, use_mrv, stats):
    stats["calls"] = stats["calls"] + 1       # Count recursive call
    
    # In improved mode, propagate forced values before branching
    if use_mrv and not propagate(board, stats):
        stats["failed_branches"] = stats["failed_branches"] + 1
        return None                           # Backtrack
        
    # Find all empty cells using a plain loop
    empty_cells = []
    for r in range(9):
        for c in range(9):
            if board[r][c] == 0:
                empty_cells.append((r, c))
                
    if len(empty_cells) == 0:                 # Base case: no empty cells remain
        return board                          # Solved!
        
    # Select cell to branch on
    if use_mrv:
        # Minimum Remaining Values (MRV): find cell with fewest candidates (NO lambda)
        best_cell = None
        min_candidates = 999
        for cell in empty_cells:
            cand_count = len(get_candidates(board, cell[0], cell[1]))
            if cand_count < min_candidates:
                min_candidates = cand_count
                best_cell = cell
        r = best_cell[0]
        c = best_cell[1]
    else:
        # Plain mode: pick the first empty cell
        first_cell = empty_cells[0]
        r = first_cell[0]
        c = first_cell[1]

    for val in get_candidates(board, r, c):
        stats["guesses"] = stats["guesses"] + 1

        for row in board:
            new_row = []
            for item in row:
                new_row.append(item)
            new_board.append(new_row)

        if result is not None:
            return result                     # Propagate solution upward
            
    stats["failed_branches"] = stats["failed_branches"] + 1
    return None                               # Backtrack

Practical 7: Combinatorial Optimization - TSP with Local Beam Search

Combinatorial Optimization • Heuristic Search • NP-Hard

Aim Theory Algorithm Source Code Code Explanation Output Viva Voce (20) Exam Variations

Aim & Objective

To solve the Traveling Salesman Problem (TSP) using Local Beam Search with beam width k and 2-city swap neighbourhood.

Theory & Core Concepts

  • TSP Formulation: Find a Hamiltonian cycle that visits all n cities exactly once and returns to the starting city with minimum total travel cost. NP-hard combinatorial problem.
  • Local Beam Search: Instead of retaining only 1 current state (like Hill Climbing), Local Beam Search maintains k candidate tours in parallel.
  • Neighbourhood Operator (2-City Swap): City 0 is anchored at the start to eliminate cyclic rotational duplicates. Neighbours are formed by swapping any pair of cities at indices 1 <= i < j < n.
  • Elitist Pooling: Combines current beam tours and all generated neighbours into a shared pool, evaluates total cost (including return edge), and retains the k best distinct tours for the next iteration.
  • Incomplete Heuristic: Beam search is not guaranteed to find the global optimum; it can get trapped in local plateaus or lose diversity.

Step-by-Step Algorithm & Dry Run

  1. Generate k distinct random initial permutations with city 0 fixed.
  2. Evaluate tour costs: sum consecutive edge weights plus edge returning from last city to city 0.
  3. Iterate up to max_iterations:
      a. Initialize candidate pool with current beam.
      b. For each tour in beam, generate all 2-city swap neighbours and add to pool.
      c. Sort pool by tour cost and select top k distinct tours.
      d. If the new beam is identical to the previous beam, break (stabilized).
      e. Update beam = next_beam.
  4. Return best-found tour and cost history.

# Practical 7: Traveling Salesman Problem (TSP) using Local Beam Search
import random                                 # Import random for generating initial tours

# Complete 5-city distance matrix (0=A, 1=B, 2=C, 3=D, 4=E)
DISTANCES = [
    [0, 10, 15, 20, 25],                      # Distances from City A
    [10, 0, 35, 25, 17],                      # Distances from City B
    [15, 35, 0, 30, 28],                      # Distances from City C
    [20, 25, 30, 0, 16],                      # Distances from City D
    [25, 17, 28, 16, 0]                       # Distances from City E
]

# Calculate total travel distance of a tour, including returning to start city
def calculate_tour_cost(tour, distances):
    total = 0                                 # Initialize total cost
    n = len(tour)                             # Number of cities
    for i in range(n):
        city_a = tour[i]                      # Current city
        city_b = tour[(i + 1) % n]            # Next city (wraps from last city back to start)
        total = total + distances[city_a][city_b] # Add edge distance
    return total                              # Return tour cost

# Generate all 2-city swap neighbours (city 0 is fixed at start to avoid duplicate rotations)
def get_neighbours(tour):
    neighbours = []                           # List of generated tours
    n = len(tour)                             # Number of cities
    for i in range(1, n - 1):                 # Select first city to swap (skip start 0)
        for j in range(i + 1, n):             # Select second city to swap
            new_tour = list(tour)             # Copy tour
            temp = new_tour[i]                # Standard swap using temp variable
            new_tour[i] = new_tour[j]
            new_tour[j] = temp
            neighbours.append(tuple(new_tour)) # Append new tour as tuple
    return neighbours                         # Return all swap neighbours

# Key function used to sort tours by cost and break ties deterministically (NO lambda)
def get_tour_sort_key(tour):
    cost = calculate_tour_cost(tour, DISTANCES)
    return (cost, tour)                       # Primary key: cost, Secondary key: tour tuple

# Local Beam Search algorithm with beam width k
def local_beam_search(distances, k=3, max_iterations=100, seed=7):
    n = len(distances)                        # Number of cities (5)
    rng = random.Random(seed)                 # Seeded random generator
    
    # Generate k distinct initial random tours starting at city 0
    beam_set = set()                          # Set avoids duplicate initial tours
    while len(beam_set) < k:
        other_cities = rng.sample(range(1, n), n - 1) # Random order of cities 1 to 4
        tour_list = [0]                       # Anchor city 0 at the start
        for c in other_cities:
            tour_list.append(c)
        beam_set.add(tuple(tour_list))        # Add to set
        
    beam = sorted(beam_set, key=get_tour_sort_key) # Sort initial beam
    cost_history = [calculate_tour_cost(beam[0], distances)] # Track best cost
    
    # Search loop
    for _ in range(max_iterations):
        pool = set(beam)                      # Elitist pool: include current tours
        for tour in beam:
            for nbr in get_neighbours(tour):  # Add all 2-city swap neighbours
                pool.add(nbr)
                
        # Sort pool and select top k distinct tours
        sorted_pool = sorted(pool, key=get_tour_sort_key)
        next_beam = sorted_pool[:k]           # Retain best k candidate tours
        
        best_cost = calculate_tour_cost(next_beam[0], distances)
        cost_history.append(best_cost)        # Record best cost at this iteration
        
        if next_beam == beam:                 # Stopping check: beam did not change
            break
        beam = next_beam                      # Update beam for next iteration
        
    best_tour = beam[0]                       # The lowest-cost tour found
    final_cost = calculate_tour_cost(best_tour, distances)
    return best_tour, final_cost, cost_history

def main():
    K = 3                                     # Beam width (3 parallel tours)
    best_tour, best_cost, history = local_beam_search(DISTANCES, k=K, max_iterations=100, seed=7)
    
    tour_with_return = best_tour + (best_tour[0],) # Append return to start city
    tour_str = " -> ".join(str(c) for c in tour_with_return)
    
    print("Best-found tour:", tour_str)
    print("City labels: 0=A, 1=B, 2=C, 3=D, 4=E")
    print("Best-found cost:", best_cost)
    print("Best cost at initialization and after each iteration:", history)
    print("Local Beam Search does not guarantee the global optimum.")

if __name__ == "__main__":
    main()

Function-by-function breakdown and key variables explaining the internal logic:

  • DISTANCES[i][j] gives the travel cost from city i to city j.
  • A tour is a permutation of city indices. City 0 is fixed at the start to avoid storing rotated copies of the same cycle.
  • tour_cost() sums consecutive edge costs. (i+1)%len(tour) includes the last-to-first edge.

# Practical 8: Classical Planning for 8-Puzzle using Breadth-First Search (BFS)
from collections import deque                 # Import deque for efficient FIFO queue operations

# Check if puzzle is solvable using inversion parity
def is_solvable(state):
    tiles = []                                # Collect tiles excluding blank (0)
    for x in state:
        if x != 0:
            tiles.append(x)
            
    inversions = 0                            # Count out-of-order pairs
    for i in range(len(tiles)):
        for j in range(i + 1, len(tiles)):
            if tiles[i] > tiles[j]:
                inversions = inversions + 1
                
    return inversions % 2 == 0                # Solvable if inversions count is even

# Generate all legal blank tile movements (UP, DOWN, LEFT, RIGHT)
def get_neighbours(state):
    neighbours = []                           # List of valid next states
    blank = state.index(0)                    # Position of the blank tile (0)
    r = blank // 3                            # Blank row (0, 1, or 2)
    c = blank % 3                             # Blank column (0, 1, or 2)
    
    # Allowed actions: (action_name, row_offset, col_offset)
    actions = [
        ("UP", -1, 0),
        ("DOWN", 1, 0),
        ("LEFT", 0, -1),
        ("RIGHT", 0, 1)
    ]
    
    for action_name, dr, dc in actions:       # Test all 4 directions
        nr = r + dr                           # New row
        nc = c + dc                           # New column
        if nr >= 0 and nr < 3 and nc >= 0 and nc < 3: # Check within 3x3 boundaries
            new_blank = nr * 3 + nc           # Target 1D index
            board = list(state)               # Copy state to list
            temp = board[blank]               # Swap blank with tile
            board[blank] = board[new_blank]
            board[new_blank] = temp
            neighbours.append((tuple(board), action_name)) # Save new board tuple and action
            
    return neighbours                         # Return all reachable boards

# Uninformed BFS planning to find the minimum-action plan
def bfs_plan(start, goal):
    if not is_solvable(start):                # Pre-check solvability
        print("No solution: initial and goal inversion parities differ.")
        return None, 0
        
    queue = deque()                           # Create FIFO queue for BFS
    queue.append(start)                       # Enqueue start state
    parent = {}                               # Maps each state to (predecessor_state, action)
    parent[start] = (None, "START")
    expanded_count = 0                        # Track expanded nodes
    
    while len(queue) > 0:                     # While queue has states to explore
        curr = queue.popleft()                # Remove oldest state (FIFO)
        
        if curr == goal:                      # Goal check
            path = []                         # Reconstruct plan backward
            while curr is not None:
                prev_state, action = parent[curr]
                path.append((curr, action))   # Record board and action taken
                curr = prev_state             # Move back to predecessor
            path.reverse()                    # Reverse to get START -> GOAL order
            return path, expanded_count
            
        expanded_count = expanded_count + 1   # Increment expanded count
        
        for next_state, action in get_neighbours(curr): # Generate successors
            if next_state not in parent:      # If not visited yet
                parent[next_state] = (curr, action) # Mark visited immediately
                queue.append(next_state)      # Enqueue for exploration
                
    return None, expanded_count               # Return None if no plan found

    GOAL = (1, 2, 3, 4, 5, 6, 7, 8, 0)        # Goal board
    
    path, expanded = bfs_plan(START, GOAL)    # Execute BFS planning
    
    if path:
        for step in range(len(path)):
            board = path[step][0]
            action = path[step][1]
            print("Step " + str(step) + ": " + action)
            for i in range(0, 9, 3):          # Print as 3x3 grid
                print(board[i], board[i+1], board[i+2])
        print("Moves:", len(path) - 1)
        print("Nodes expanded (excluding goal):", expanded)

if __name__ == "__main__":
    main()

Practical 9: Uninformed Search - DFS for Water Jug Problem

Uninformed Search • Depth-First Search • LIFO Stack

Aim Theory Algorithm Source Code Code Explanation Output Viva Voce (17) Exam Variations

Aim & Objective

To solve the classical Water Jug Problem using Depth-First Search (DFS) with a LIFO stack.

Theory & Core Concepts

  • Problem Formulation: Two jugs with integer capacities A and B without markings, measuring target quantity T in either jug. Initial state is (0, 0).
  • Six Elementary Operations:
    1. Fill Jug A: (A, b)
    2. Fill Jug B: (a, B)
    3. Empty Jug A: (0, b)
    4. Empty Jug B: (a, 0)
    5. Pour A into B: (a - t, b + t), where t = min(a, B - b)
    6. Pour B into A: (a + t, b - t), where t = min(b, A - a)
  • Diophantine Solvability Condition: Target T can be measured if and only if T <= max(A, B) and T is divisible by gcd(A, B).
  • DFS Characteristics: Uses LIFO stack. Explores deep branches before backtracking. Path depends on operator ordering; finds a valid path, but is not guaranteed to be shortest.

    b = state[1]                              # Water in Jug B

    pour_a_to_b = min(a, cap_b - b)           # Limited by water in A or remaining space in B
    pour_b_to_a = min(b, cap_a - a)           # Limited by water in B or remaining space in A

        ((cap_a, b), "Fill A"),               # 1. Fill Jug A completely
        ((a, cap_b), "Fill B"),               # 2. Fill Jug B completely
        ((0, b), "Empty A"),                  # 3. Empty Jug A completely
        ((a, 0), "Empty B"),                  # 4. Empty Jug B completely
        ((a - pour_a_to_b, b + pour_a_to_b), "Pour A -> B"), # 5. Pour from A into B
        ((a + pour_b_to_a, b - pour_b_to_a), "Pour B -> A")  # 6. Pour from B into A
    ]

    if target > max(cap_a, cap_b) or target % gcd(cap_a, cap_b) != 0:
        print("No solution for these capacities and target.")

    parent = {}                               # Tracks visited states and action taken
    parent[start_state] = (None, "START")

Aim & Objective

To solve the 8-Queens problem and evaluate the efficiency gains of Backtracking with Forward Checking compared to Plain Backtracking.

Theory & Core Concepts

  • Problem Formulation: Place 8 queens on an 8x8 chessboard such that no two queens attack each other along any row, column, or diagonal.
  • Representation: 1D array queens[row] = col. Each row naturally receives at most one queen.
  • Conflict Conditions: Queens at (r, col_r) and (row, col) conflict if:
    • col_r == col (same column)
    • abs(col_r - col) == row - r (same diagonal)
  • Forward Checking Lookahead: Whenever a queen is placed at (row, col), immediately look ahead and remove col, col - delta, col + delta from the candidate domains of all remaining future rows later > row.

# Check if placing a queen at (row, col) is safe from already placed queens
def safe(queens, row, col):
    for r in range(row):                      # Check all previously placed queens
        # Conflict if in the same column OR along the same diagonal
        if queens[r] == col or abs(queens[r] - col) == row - r:
            return False                      # Position is under attack
    return True                               # Safe to place queen

# Solver function supporting both Plain Backtracking and Forward Checking
def solve_queens(n=8, forward_checking=False):
    queens = []                               # Build queens array using a simple loop
    for i in range(n):
        queens.append(-1)                     # -1 means unassigned
        
    solutions = []                            # List to store all valid board arrangements
    stats = {"calls": 0, "candidates_tried": 0, "domain_wipeouts": 0} # Performance metrics
    
    # Recursive search function
    def search(row, domains):
        stats["calls"] = stats["calls"] + 1   # Count recursive call
        
        if row == n:                          # Base case: all n queens successfully placed
            solutions.append(queens.copy())   # Save independent copy of the solution board
            return
            
        # Determine available columns for this row (NO ternary operator)
        if forward_checking:
            options = sorted(domains[row])
        else:
            options = list(range(n))
            
        for col in options:                   # Try each column candidate
            stats["candidates_tried"] = stats["candidates_tried"] + 1 # Count candidate attempt
            
            if not safe(queens, row, col):    # Skip if attacked by earlier queens
                continue
                
            queens[row] = col                 # Place queen at (row, col)
            
            if forward_checking:              # Forward Checking mode: lookahead & prune
                # Copy future domains using plain loop (NO list comprehension)
                next_domains = []
                for d in domains:
                    next_domains.append(d.copy())
                    
                possible = True               # Flag for domain wipeout
                
                # Prune attacked columns from all future rows (later > row)
                for later in range(row + 1, n):
                    delta = later - row       # Diagonal distance
                    # Remove attacked columns using plain discard()
                    next_domains[later].discard(col)
                    next_domains[later].discard(col - delta)
                    next_domains[later].discard(col + delta)
                    
                    if len(next_domains[later]) == 0: # If any future row has 0 legal columns
                        possible = False      # Domain wipeout detected!
                        break                 # Stop pruning future rows
                        
                if possible:                  # If all future rows still have at least 1 legal spot
                    search(row + 1, next_domains) # Recurse safely
                else:
                    stats["domain_wipeouts"] = stats["domain_wipeouts"] + 1 # Early failure detected
            else:
                search(row + 1, domains)      # Plain mode: recurse without pruning domains
                
            queens[row] = -1                  # Backtrack: remove queen and try next column
            
    # Initial domains: every row initially has all columns {0, 1, ..., n-1} available
    initial_domains = []
    for i in range(n):
        initial_domains.append(set(range(n)))
        
    search(0, initial_domains)                # Start search from row 0
    return solutions, stats

# Practical 11: Rule-Based Chatbot using Regular Expressions (re module)
import re                                     # Import regular expressions module

# Ordered list of (pattern, template_response) rules
RULES = [
    # Rule 1: Capture user name (e.g., "my name is Rahul")
    (r"\bmy name is (?P<name>[a-z]+(?: [a-z]+)*)$", "Nice to meet you, {name}!"),
    
    # Rule 2: Bot identity query
    (r"\bwhat is your name\b", "I am AI-Bot, a rule-based chatbot."),
    
    # Rule 3: Pleasantry / greeting enquiry
    (r"\bhow are you\b", "I am fine, thank you!"),
    
    # Rule 4: Capture positive emotion (e.g., "I feel happy")
    (r"\bi (?:am(?: feeling)?|feel) (?P<mood>happy|excited|good)\b", "Glad you feel {mood}!"),
    
    # Rule 5: Capture general emotion
    (r"\bi (?:am(?: feeling)?|feel) (?P<mood>[a-z]+)\b", "You said you feel {mood}. Thank you for sharing."),
    
    # Rule 6: Subject questions about Artificial Intelligence
    (r"\b(artificial intelligence|ai)\b", "AI builds systems that perform tasks such as reasoning and problem solving."),
    
    # Rule 7: Subject questions about Chatbots
    (r"\bchatbot\b", "A chatbot is a program that converses with a user."),
    
    # Rule 8: Technology question
    (r"\b(language|python)\b", "I am written in Python using the re module."),
    
    # Rule 9: Concept question
    (r"\b(pattern matching|regular expressions?)\b", "Pattern matching checks input against predefined text patterns."),
    
    # Rule 10: Gratitude
    (r"\b(thanks|thank you)\b", "You are welcome!"),
    
    # Rule 11: General greeting (placed after specific rules)
    (r"\b(hello|hi|hey)\b", "Hello! How can I help you?")
]

DEFAULT = "I do not have a rule for that. Try asking about AI or chatbots."

# Clean and normalize input text
def preprocess(text):
    text = text.lower().strip()                # Convert text to lowercase and strip edges
    text = re.sub(r"[^\w\s]", " ", text)      # Replace punctuation marks with spaces
    words = text.split()                      # Split into individual words
    cleaned_text = " ".join(words)            # Rejoin words with single space
    return cleaned_text

# Match input against predefined rules and return response
def respond(user_input):
    text = preprocess(user_input)             # Clean the incoming user message
    
    # Check for exit command
    if re.fullmatch(r"bye|goodbye|exit|quit", text):
        return "Goodbye!", True               # Return goodbye message and stop flag True
        
    if len(text) == 0:                        # If user entered an empty message
        return "Please type a message.", False
        
    # Check each rule in priority order
    for pattern, reply in RULES:
        match = re.search(pattern, text)      # Search for pattern in user text
        if match:                             # If a pattern matches
            values = match.groupdict()        # Extract captured variables (name, mood)
            if "name" in values:              # Capitalize user's name if captured
                values["name"] = values["name"].title()
            return reply.format(**values), False # Inject captured values into response
            
    return DEFAULT, False                     # Return default fallback if no rule matched

def main():
    print("AI-Bot: Hello! Type bye, goodbye, exit or quit to stop.")
    
    while True:                               # Chat loop
        message = input("You: ")              # Read user message from terminal
        if len(message.strip()) == 0:         # Skip empty inputs
            continue
            
        reply, should_stop = respond(message) # Generate reply from chatbot
        print("AI-Bot:", reply)               # Print bot's answer
        
        if should_stop:                       # If user typed an exit word
            break                             # Exit the loop

if __name__ == "__main__":
    main()

Detailed Code Explanation

Function-by-function breakdown and key variables explaining the internal logic:

  • RULES is an ordered list of (pattern,response) pairs. This version uses one deterministic reply per rule to make revision easier.
  • preprocess() converts text to lowercase, replaces punctuation with spaces and collapses repeated whitespace.
  • respond() checks a full-message exit command first. It handles empty input separately.
  • It tries re.search(pattern,text) for each rule and stops at the first match.
  • \b matches word boundaries, so the greeting hi does not accidentally match inside this.
  • (?P<name>...) and (?P<mood>...) are named capture groups. match.groupdict() retrieves the captured values.
  • reply.format(**values) places them into {name} or {mood} in the reply. Captured names are title-cased.
  • If no rule matches, return DEFAULT. The main loop prints the reply and stops when the returned stop flag is true.
  • EOFError and KeyboardInterrupt are handled to end cleanly if input closes or Ctrl+C is pressed.

Examples: HELLO!!! gives a greeting; My name is Akamal Shaikh inserts the name; This is a hit does not trigger hi; bye exits. bye bye does not exit because it is not one exact command.

Viva Voce Questions & Model Answers

Frequently asked laboratory exam and oral viva questions with model examiner responses:

Q1. What is a chatbot?
A program that interacts with a user through conversation, usually text or voice.
Q2. What is a rule-based chatbot?
A chatbot whose replies are selected using manually written rules rather than learned behaviour.
Q3. What is pattern matching?
Checking whether input text contains or follows a specified pattern.
Q4. What is a regular expression?
A compact notation describing a pattern of characters or words.
Q5. What does Python's re module provide?
Regular-expression operations such as search, fullmatch and substitution.
Q6. What is a rule's structure?
A condition/pattern and an associated response; ours stores each as a pair.
Q7. Why preprocess input?
To make matching less sensitive to capital letters, punctuation and repeated spaces.
Q8. What does `\b` do?
It represents a word boundary, helping match complete words instead of substrings.
Q9. What are capture groups?
Pattern portions that store matched text for later use, such as inserting a user's name into a reply.
Q10. What if no pattern matches?
The program gives a fallback response explaining its limited topic coverage.
Q11. Why does rule order matter?
The first matching rule wins, so broad rules could hide more specific ones if placed earlier.
Q12. How does it stop?
re.fullmatch recognises bye, goodbye, exit or quit as the complete normalised message.
Q13. What is its response-time complexity?
A useful rough estimate is O(R*L) for R simple rules on input length L. Regex complexity depends on the patterns; this is not a universal guarantee for arbitrary regexes.
Q14. What was ELIZA?
An early chatbot that generated conversational replies using pattern matching and substitution rules.
Q15. Rule-based versus machine-learning chatbot?
Rules are explicitly programmed; an ML system learns patterns from data and may generalise to new wording.
Q16. What is the Turing Test?
An evaluation of whether an evaluator can distinguish a machine's conversational responses from a human's under the test's conditions.
Q17. What are this chatbot's limitations?
Limited rules, no learned understanding, no persistent conversational memory and weak handling of unanticipated wording.
Q18. How could it remember the user's name?
Store the captured name in a session dictionary and consult it when later questions refer to the name.
Q19. How can it be improved?
Add focused rules, synonyms, contextual state or a learned intent classifier, and test conflicting patterns.
Q20. Give applications.
Small FAQ systems, college enquiry assistants and simple support menus.

Practical Exam Variations & Edge Cases

Common Examiner Test Cases & Code Tweaks:
  • Difference between re.search, re.match and re.fullmatch? Search looks anywhere; match checks from the beginning; fullmatch requires the entire input to match.
  • What does the r prefix mean? A raw string preserves backslashes for the regex parser; r"\bhi\b" expresses word boundaries clearly.
  • Add a college rule. Add (r"\bcollege\b", "This is an AI laboratory chatbot.") before the general greeting rule.
  • Does capturing a name mean it is remembered? No. This code uses the name only in the current reply. Persistent memory requires extra state.
  • How would you add several replies per rule? Store a list of response strings and use random.choice() after a match, before formatting captured groups.

Universal Python Viva Questions (Top 15)

These 15 Python questions are repeatedly asked by examiners regardless of which practical you draw:

Q1. List versus tuple?
A list can be changed; a tuple cannot. Tuples containing hashable values can be dictionary keys or set elements.
Q2. Why use a set?
For unique elements and efficient membership tests, typically O(1) average time.
Q3. Why use a dictionary?
To associate states with parents/costs or labels with values; lookup is typically O(1) average time.
Q4. What does `yield` do?
It returns the next item from a generator while preserving the function's state for later iteration.
Q5. What does `return None` mean?
The function returns Python's absence value. In these searches it often signals no solution.
Q6. Why distinguish `None` from an empty list?
An empty path or collection can sometimes be a valid result; explicitly checking is None avoids confusing it with failure.
Q7. What does `if __name__ == "__main__"` do?
It runs the demonstration only when the file is executed directly, allowing functions to be imported without starting the demo.
Q8. What is a base case?
The condition that ends recursion, such as all rows assigned or depth zero.
Q9. What is a shallow copy?
A new outer container that still refers to nested objects. For a grid, copying each row separately is needed when rows will be modified.
Q10. Why avoid `[[0]*9]*9` for an editable Sudoku?
It repeats references to the same row. A change in one row can appear in all rows. Use a comprehension to create separate rows.
Q11. What does `[::-1]` do?
It returns a reversed sequence; parent reconstruction uses it to put a goal-to-start trace into start-to-goal order.
Q12. What is a priority queue?
A structure that removes the item with the best priority, not necessarily the oldest or newest item.
Q13. What are completeness and optimality?
Completeness means finding a solution if one exists under stated assumptions; optimality means returning a best-cost solution.
Q14. What is a branching factor?
The number of successors per state, or an upper/average value used in search analysis.
Q15. What is the difference between a state and a node?
A state describes the world; a search node may additionally store a path, cost, parent and action. Several search nodes can represent the same state.
